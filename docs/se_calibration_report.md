## Methodology

- **Puzzle set**: 200 puzzles (100 from top1465 SE 8–10 range; 100 from forum_hardest_1905_11plus SE 10+ range).
- **SE rater**: 1to9only Java fork compiled from source, `diuf.sudoku.test.serate`.
- **Our rater**: `rate-batch --mode full` (Rust, release build).
- **Join key**: exact 81-char puzzle string.
- **Metric compared**: SE `ED` field (ER = overall hardest technique) vs our `se_score` = max(base_rating) across fired frontier techniques.

### CFC False Positive (Notable Bug)

The max-overestimate puzzle (`4.1.6....3.....2........8..15.2.....6...`) has 18 clues and
SE rates it **4.5** (hidden_triple territory). Our rater fires `cell_forcing_chain` and
returns `se_score=7.5`. This is a false positive: CFC should not be required on a puzzle
solvable at SE 4.5. Indicates a CFC implementation bug where it triggers unnecessarily
when T2 techniques suffice. This inflates our scores for easy puzzles and is a separate
issue from calibration.

### als_xz Bucket Split

The als_xz bucket has bimodal structure — not a single calibration error:
- **SE ≤ 7.5 (16 puzzles)**: SE mean=7.09, we report 7.5 → **overestimate by +0.41**.
  SE rates some ALS pairs at 6.7–7.2 (simpler ALS). Our fixed base=7.5 is too high here.
- **SE > 7.5 (24 puzzles)**: SE mean=8.78, we report 7.5 → **underestimate by -1.28**.
  SE sees Region FC or Dynamic Forcing Chains on top; our cascade stops at 7.5.
- A single weight edit to als_xz base cannot fix both halves. The correct fix is
  (a) add chain-length scaling to als_xz (like AIC), and (b) implement Region FC.

## Verdict

The overall RMS gap of 1.79 SE units has two components: (a) **calibration bias** — per-technique base-rating offsets from SE ground truth, correctible by applying the weight edits above (cell_fc, als_xz, naked_quad, hidden_quad); (b) **coverage gaps** — techniques we don't implement (Region FC, Dynamic FC, Nested AIC, X-Cycles/Forcing X-Chains 6.6+) cause 59% of our T4Plus puzzles to have SE ER > 9.0, which our sentinel at 7.5 systematically underestimates by 3.1 SE units on average. Applying the per-technique mean corrections reduces RMS from 1.79 to 0.67 (corrected residual). The remaining 0.67 residual is dominated by within-bucket variance from coverage — weight edits alone are not sufficient to close the gap for hard puzzles (SE > 8.5). A CFC false-positive bug also inflates scores for a subset of easy puzzles.

### `"none"` bucket (24 puzzles, mean diff = −3.53)

These 24 puzzles have empty frontiers in our rater (SE ER 10.9–11.1). They are SE 11+ puzzles where our rater produces `wave_depth=1, solved=False` — the cascade finds no applicable technique. These require Nested AIC or Dynamic Forcing Chains (SE > 10.0) which are not implemented. The sentinel of 7.5 understates them by 3.5 SE units. This is pure coverage, not calibration.
